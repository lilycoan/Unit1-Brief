**Why this order:**
- Every uncertain input is declared once in `data.js`, with its low, central, high, and source.
- The calculations then run in one of three modes: all low, all central, or all high. A fourth mode moves one named input while the rest stay central.
- Building that in step 1 means every feature is range-aware from the start. It also means the "shared inputs moved once" rule for drivers (PUE, water factors) holds automatically, so step 6 adds no rework.
- Agent sessions come before media because they change the existing rows. Media only adds new ones.

**The main alternative:** build the features first, with point estimates, and add ranges at the end. That puts something visible on the page sooner. The cost is reworking every feature's math afterwards.

**Is this order right, or do you want to change the priority?** For example, citations could run alongside each feature instead of forming their own step at the end. That catches missing sources earlier, but it makes each step bigger.
